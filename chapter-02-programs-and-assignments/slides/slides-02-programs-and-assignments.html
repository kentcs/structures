Programs and Assignments

How x = 2; print x; becomes output

Develop the grammar, AST, and execution trace on the whiteboard. The second lecture follows the implementation code. Current language: nonempty programs containing assignment and print statements, arithmetic expressions with integers, floats, unary minus, identifiers, and flexible semicolon runs. Assignment is a statement, not an expression.

The New Program

x = 2;
print x;
2

What must the interpreter remember?

Begin with the behavior rather than the implementation. Chapter 1 could evaluate one expression and return one value. This source contains two actions. The first statement must affect the second. Ask what must persist after the assignment finishes. Use the whiteboard to identify the name x, the value 2, statement order, and visible output.

Expressions and Statements

An expression produces a value.

x + 3 * 4

A statement performs an action.

x = 2
print x
The right side of assignment is an expression. The argument of print is also an expression. Assignment changes stored state. Print produces output. Topic 2 uses only assignment and print statements. Do not introduce expression statements or compound statements here.

A Program Contains Statements

program = statement_list

statement = assignment_statement
          | print_statement

A statement list contains at least one statement.

Develop the hierarchy on the whiteboard: program, statement list, statement. The program is the parser's new top-level unit. The statement list preserves source order. Topic 1 used expression as the public parser's entry point. Topic 2 uses program.

Separating Statements

Source Valid?
x = 2 Yes
x = 2; print x Yes
;;;x = 2;;;print x;;; Yes
x = 2 print x No
empty input No
Ask the class to infer the rule before showing the EBNF on the next slide. Leading and trailing semicolons are allowed. One or more semicolons must occur between adjacent statements. A single statement needs no semicolon. Newlines are whitespace and do not replace separators.

Statement List Grammar

statement_list = { ";" } statement
                 { ";" { ";" } statement }
                 { ";" }

Braces mean zero or more repetitions.

Read the rule in three parts. First, consume optional leading semicolons and one required statement. Second, repeat a separator followed by another statement. Third, allow trailing semicolons. The first statement outside braces makes the list nonempty. There are no brackets or compound statements in Topic 2.

The Two Statement Forms

assignment_statement = <identifier> "=" expression

print_statement = "print" expression
x = 2
print x
The first token distinguishes the two forms. Assignment begins with an identifier. Print begins with the print keyword. The expression grammar remains separate and appears on the right side of each statement form.

Identifiers in Expressions

factor = <number>
       | <identifier>
       | "(" expression ")"
y = x + 3 * 4

What value does x have?

Simple Expressions already had numbers, parentheses, floats, and unary minus. Topic 2 adds identifiers as a factor form. The parser can recognize x as an identifier node without knowing its value. The evaluator must obtain that value from the environment at runtime.

Expressions Carry Forward

term = unary { ("*" | "/") unary }
unary = "-" unary | factor
x = -1.5
y = 3 * -2
Do not reteach this as new Topic 2 material. The expression parser carries forward from Simple Expressions. This slide is here to show that assignment does not replace expression parsing. Right-hand sides still use the same expression rules, now with identifiers available as factors.

The Program Tree

program
  statement_list
    assign x
      number 2
    print
      identifier x

The tree preserves statement order.

Draw the full AST on the whiteboard. Program contains one statement-list node. Its list holds an assign node followed by a print node. The assignment target is the name x. Its expression is the number node. Print contains an identifier expression. Semicolons do not need nodes.

The Environment

An environment maps names to values.

Name Value
x 2

The program begins with an empty environment.

Represent the environment as a table on the whiteboard. The Python implementation uses a dictionary, but the concept is a mapping. Before x = 2, the table has no x row. After assignment, x maps to 2. Topic 2 needs only one environment shared by the whole program.

Assignment Changes the Environment

x = 2
  1. Evaluate the expression 2.
  2. Associate the result with x.
{} becomes {"x": 2}
Trace the semantic rule without showing evaluator code. Evaluation of the right side happens before the update. This order later supports x = x + 1 because the right side reads the old value and assignment then stores the new one. Assignment returns no Vertex value in this chapter.

Print Reads the Environment

print x
  1. Look up x.
  2. Obtain 2.
  3. Print 2.

An unknown name causes an evaluation error.

The parser can recognize the identifier without proving that a value exists. Lookup happens during evaluation. If the environment has no binding for x, evaluation raises an unknown-identifier error. Keep the discussion to one environment. Parent environments belong to later scope topics.

One Environment for the Program

Statement Environment afterward Output
x = 2 {"x": 2}
print x {"x": 2} 2
y = x + 3 * 4 {"x": 2, "y": 14}
print y {"x": 2, "y": 14} 14
Use the supplied example.v program. Execute one row at a time on the whiteboard. Each statement receives the same environment. Assignment mutates it. Later statements see earlier bindings. Arithmetic precedence still groups 3 * 4 before addition.

Assignment Is a Statement

Valid:

x = 2;
print x;

Invalid in Topic 2:

print (x = 2)
State the design boundary directly. The expression parser does not recognize equals. Later topics may introduce assignment expressions and the additional parser decisions they require. Do not anticipate that implementation in this lecture.

Real Parser Code: Go

case token.ADD, token.SUB, token.NOT, token.XOR, token.AND, token.TILDE:
    pos, op := p.pos, p.tok
    p.next()
    x := p.parseUnaryExpr()
    return &ast.UnaryExpr{OpPos: pos, Op: op, X: x}

Same move: consume the operator, parse the operand, build a tree node.

This excerpt is from Go's standard parser in go/parser/parser.go, in parseUnaryExpr. It is larger than Vertex because Go has more unary operators and richer AST structs, but the parsing pattern is the same as parse_unary in Simple Expressions. The front end of a real language system still has to recognize tokens, choose grammar rules, and build tree nodes that later stages can use.
