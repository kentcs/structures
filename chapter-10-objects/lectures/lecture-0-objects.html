Objects in Vertex

  • Object literals construct string-keyed records.
  • Fields can be read, updated, and added.
  • Equality compares keys and values, regardless of insertion order.
  • Display preserves field insertion order.

A Record with Named Fields

student = {"name": "Ada", "score": 87};

Reading, Updating, and Adding

student = {"name": "Ada", "score": 87};
print(student.score);
student.score = student.score + 3;
student.passed = true;
print(student.score);
print(student.passed);

Prints 87, then 90, then true.

Equality Ignores Insertion Order

a = {"name": "Ada", "score": 87};
b = {"score": 87, "name": "Ada"};
print(a == b);

Prints true: the same keys have equal values.

Display Preserves Insertion Order

print(a);
print(b);
Object Field order in the output
a name, then score
b score, then name

Equal objects can have different printed field orders.

Reading a Field

Objects and Lists Together

students = [
    {"name": "Ada", "scores": [87, 93]},
    {"name": "Lee", "scores": [82, 90]}
];
students[0].scores[1] = 95;

Each suffix selects the next value.

Objects and Environments

A shared host representation does not make them the same thing.

A Field Named $PARENT

grandparent = {"name": "Mae", "birthplace": "Kent"};
parent = {"name": "Lee", "$PARENT": grandparent};
print(parent["birthplace"]);

Missing-key error. No search through grandparent.

Braces Depend on Context

student = {"score": 87};

if (student.score >= 60) {
    student.passed = true;
}

An expression constructs a value. A block contains statements.

Object Literal Grammar

Extended Backus-Naur Form (EBNF)

object_expression ::= "{" [ field { "," field } ] "}"
field             ::= expression ":" expression

Syntax permits an expression; evaluation requires a string key.

Dot Notation in the Parser

student.score
student["score"]
complex
  base:  identifier("student")
  index: string("score")

One abstract syntax tree (AST), two spellings.

Field Assignment Tree

student.score = 90;

Construction and Status

For each field, in source order:

  1. Evaluate the key; check status and type.
  2. Reject a duplicate key.
  3. Evaluate the value; check status.
  4. Store the field.

exit stops construction before later fields run.

Shallow Copy Shares Nested Values

a = {"scores": [87, 93]};

Conceptual shallow copy: two objects share one list.

Deep Copy Separates Nested Values

a = {"scores": [87, 93]};
b = copy(a);
b.scores[1] = 100;

Shared Children Stay Shared

child = {"score": 87};
a = {"first": child, "second": child};
b = copy(a);

Copying a Cycle

a = {};
a.self = a;
b = copy(a);

Following the Copied Self-Reference

a = {}; a.self = a;
b = copy(a);
b.score = 90;
print(b.self.score);
print(a);
Read Result
b.self.score 90
a {"self": {...}}

The new score belongs to b; a stays unchanged.

Considerations

New object fields add named facts; list writes use existing positions.

Rebinding one alias leaves the shared object unchanged.

Evaluation checks the base type, key type, and field existence.

Working with Objects

Operation Result
type({}) "object"
string(obj) Insertion-order representation
copy(obj) Independent deep copy
number(obj), boolean(obj) Type error

Use fields for named facts; keep field lookup direct.
